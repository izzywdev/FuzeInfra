# Design — Realtime client messaging + edge hardening

**Status:** proposed (no code changes in this PR — this is the decision record)
**Scope:** FuzeInfra (edge tier, network policy, Centrifugo deployment) + delegated
FuzeFront work (identity abstraction, device registry, `maxDevices`)
**Supersedes:** nothing. **Related:** `docs/design/a2a-federation-rfc.md`,
`docs/consuming-repos/ONBOARDING_A_CONSUMER_APP.md`

---

## 1. Problem

Three requirements arrived together, and they are usually conflated. They are not
the same problem and must not share an enforcement point:

1. **Realtime delivery** — push server-originated events to a user's browser and
   mobile devices, surviving pod restarts, rollouts and mobile network churn.
2. **Multi-device identity + `maxDevices`** — FuzeFront must know a user's devices,
   cap concurrent ones, and let a user evict a device.
3. **Vendor independence of the IdP** — swapping Authentik for Keycloak must not
   change one line outside FuzeFront.

The platform already has two of the three moving parts deployed (Kafka, Redis) and
one live example of the anti-pattern (`a2a-relay`).

### 2.1 Ingress is a wildcard, not an allowlist

`terraform/contabo/cloudflare.tf:102-110` ends the tunnel config with a catch-all:

```hcl
ingress_rule { service = "http://traefik.kube-system:80" }
```

With `cloudflare_record.prod_wildcard` (`*.prod.fuzefront.com` → tunnel), **any
Ingress declared in the cluster is internet-reachable the moment it exists.** No
terraform change, no review step. The exposure decision is made entirely by which
Cloudflare Access app matches, and a more-specific app always beats the
`*.${prod_domain}` wildcard.

### 2.2 Traefik is a single replica — confirmed

```
kube-system   traefik   1/1
```

`argocd/cluster-bootstrap/traefik-clusterip.yaml` is a `HelmChartConfig` that sets
only `service.type: ClusterIP`; it never touches replicas, so Traefik runs at the
k3s bundled default. Every host on `*.prod.fuzefront.com`, plus `app`/`plan`/
`fuzehub` and the `fuzefront.com` apex, funnels through one pod with no connection
draining. A Traefik restart drops every long-lived connection in the cluster
simultaneously.

### 2.3 The network is flat

`kind: NetworkPolicy` exists in exactly three files repo-wide:
`helm/fuzeinfra/templates/service-chroma-provisioning.yaml`,
`helm/fuzeinfra/templates/custom-hostname-api.yaml`,
`helm/litellm/templates/networkpolicy.yaml`. There is no default-deny anywhere.

Node segmentation exists (`global.durableNodeTaint`, `fuzeinfra.io/durable=true:NoSchedule`,
plus `nodeSelector` on the stateful services) but splits on **storage durability**,
not exposure. Every pod in the chart includes `fuzeinfra.durableToleration`
(`_helpers.tpl:150`) — the public relay included — so internet-facing pods schedule
onto the same nodes as Postgres and Neo4j.

### 2.4 `a2a-relay` is the anti-pattern, in production

```
fuzeinfra   a2a-relay   1/1
```

- Publicly reachable at `relay.prod.fuzefront.com` via a `non_identity` Access app.
- **No bearer.** `helm/fuzeinfra/templates/a2a-relay.yaml` documents v0 as OPEN:
  "the capability is the unguessable `cse_...` session-id" — a value that appears
  in logs and in this conversation's own transcripts.
- All state in a process-local dict (`helm/fuzeinfra/files/a2a-relay/relay.py:38`,
  `PEERS = {}`). `replicas: 1` is pinned in `values.yaml:1473` **because** of this.
  Total session loss on any restart, drain or node eviction. Cannot scale.
- Runs `python:3.12-slim` with `pip install websockets==12.0` at container start —
  an unpinned network fetch on every pod start, on a public listener.

### 2.5 Datastore admin surfaces are one tfvars line from public

`helm/fuzeinfra/templates/ingress.yaml` publishes `elasticsearch` and `chromadb`
(raw datastore HTTP APIs, no auth of their own) as hostnames, plus `neo4j` /
`neo4j-bolt` from `neo4j-ingress.yaml`. They are protected **only** by the
`*.${prod_domain}` Access wildcard.

`terraform/contabo/materialized/consumers.tfvars` is generated by an auto-PR flow
from each consumer repo's `deploy/cf/hosts.yaml`. Its own header states the policy:

> bypass only for hosts whose app owns its own auth — admin UIs get gated Access
> apps in cloudflare.tf instead

That policy is **a comment, not a check.** A consumer entry for a colliding label
would publish a raw datastore to the internet through the normal merge path.

### 2.6 The IdP faces the browser today

`authentik-server` / `authentik-worker` run in the `fuzefront` namespace, and
`terraform/contabo/cloudflare.tf:632` publishes
`${var.authentik_host}/application/o` with a `bypass` / `everyone = true` policy.

The path scoping is correct and deliberate (the admin UI and flow UI stay behind
the wall). But the OIDC **protocol** endpoints are public by necessity of the
redirect flow, which means the browser is redirected to Authentik, learns the IdP
hostname, and receives Authentik-issued tokens. **This directly contradicts the
vendor-independence requirement** — today, swapping to Keycloak changes a public
hostname, the discovery document, the `iss` claim, and every JWKS URL that any
downstream validator holds.

## 3. Requirements

**Functional**

- R1 Deliver server-originated events to all of a user's connected devices.
- R2 Survive gateway pod restart/rollout without losing messages (resumable).
- R3 Survive client-side disconnection (mobile backgrounding, network switch).
- R4 Per-device addressing, presence, and per-device read cursors.
- R5 `maxDevices` — cap concurrent registered devices per user; user-initiated eviction.
- R6 Horizontal scale of the connection tier.

**Constraints**

- C1 **Do not introduce a new datastore.** Kafka and Redis are already deployed
  (`values.yaml:471`, `values.yaml:374`).
- C2 **SSE is reserved for remote MCP transport** and is not available as the
  browser push channel (§4.2).
- C3 **The IdP must never face the browser or any non-FuzeFront service.** Swapping
  Authentik → Keycloak changes nothing outside the FuzeFront repo.
- C4 Prod is GitOps — every change lands as a commit that Argo syncs.

**Non-goals**

- Not redesigning service↔service messaging. Kafka stays.
- Not building an IdP. Authentik stays; it just stops being externally visible.
- Not solving the §2.7 outages. Recorded, delegated.

## 4. Decisions

### 4.1 Adopt Centrifugo; do not build the gateway

**Decision:** deploy [Centrifugo](https://centrifugal.dev) as the connection tier,
in the new edge namespace, with the Redis engine and its Kafka consumer.

Centrifugo covers R1–R4 and R6 out of the box: channels with per-user/per-device
addressing, presence, **history + recovery** (the resumable-cursor and replay-buffer
mechanism), JWT auth against a configurable JWKS, a Redis engine for horizontal
scale-out, and a built-in Kafka consumer so publishing services keep publishing to
Kafka exactly as they do today.

Rejected alternatives:

| Option | Why not |
|---|---|
| Build on `socket.io` + Redis adapter | We own reconnect, presence expiry, gap replay — the three parts that are hard and that `a2a-relay` already got wrong. |
| Soketi | No history/recovery. R2 and R3 become ours again. |
| NATS + JetStream | Genuinely new infra beside Kafka. Violates C1 with no offsetting benefit. |
| Ably / Pusher (hosted) | Per-message pricing, external egress dependency on the delivery path, and a third auth surface to reconcile with C3. |
| Extend `a2a-relay` | It is the thing being replaced. |

**Kafka is NOT the last hop.** It remains the durable event source. Kafka cannot
address individual browsers: browsers cannot speak the protocol, partitions are the
unit of parallelism so topic-per-user is a cluster-killer, and consumer-group
semantics are wrong for an ephemeral per-connection subscription. Any Kafka-only
design still needs a gateway process — so Kafka does not remove the component, it
just sits behind it. Correct split:

```
services ──▶ Kafka            durable log, ordering, replay, service↔service
                │
                ▼
          Centrifugo          consumes Kafka, owns connections
                │
                ├── Redis     per-user channels, presence, connection registry,
                │             Streams as the recovery buffer
                ▼
          browser / mobile
```

Both datastores are already deployed. Centrifugo is a stateless service over
infrastructure we already run — not new infrastructure.

### 4.2 Client transport is WebSocket. SSE is reserved for MCP.

SSE is the remote transport for the `*-mcp` pods (§2.8) and is not repurposed as
the browser push channel. Client connections are WebSocket only.

Consequence, and it is not incidental: **long-polling fallback must be disabled.**
The polling→upgrade handshake is the only reason WebSocket deployments need sticky
sessions at all. Once a WebSocket is upgraded it is pinned to one pod by TCP for
its lifetime — that is stronger than LB stickiness, and it is free. With polling
disabled there is no cookie affinity anywhere in this design, and Traefik needs no
sticky-service configuration.

### 4.3 Identity: FuzeFront is the only thing that knows the IdP exists

This is the load-bearing decision for C3, and it has three parts.

**(a) The browser never talks to the IdP.** FuzeFront reverse-proxies the OIDC flow
under its own origin — `api.fuzefront.com/auth/*` → `authentik-server.fuzefront.svc`
— so the IdP hostname never appears in a redirect, a discovery document, or a
token. Authentik's external issuer/base URL is set to the FuzeFront-proxied URL so
the `iss` claim matches what the browser sees. Swapping to Keycloak becomes a
proxy-target change plus an issuer setting, both inside FuzeFront.

This is preferred over having FuzeFront collect credentials directly (a
direct-grant / ROPC shape): ROPC is removed in OAuth 2.1, and routing credentials
through FuzeFront forfeits MFA, passkeys and social login — a large price for the
same independence the proxy already buys.

**Once this lands, delete `cloudflare_zero_trust_access_application.authentik_oidc_endpoints`
and its bypass policy** (`terraform/contabo/cloudflare.tf:632`). That resource is
the current public exposure of the IdP; the proxy is what makes removing it
possible. Removing it before the proxy exists breaks login.

**(b) FuzeFront issues its own tokens.** The IdP's access token is consumed by
FuzeFront and never forwarded. FuzeFront signs its own short-lived JWT with its own
keys and publishes its own JWKS. Every downstream validator — Centrifugo included —
validates against **FuzeFront's** JWKS, never the IdP's. Without this rule, IdP
coupling spreads to every service that validates a token and C3 is lost no matter
how well the proxy is built.

**(c) User identity is FuzeFront-owned.** The primary key is a FuzeFront UUID, not
the IdP's `sub`:

```
users(id UUID PK, ...)
identity_links(provider TEXT, external_sub TEXT, user_id UUID FK, PRIMARY KEY(provider, external_sub))
```

An IdP migration writes new `identity_links` rows. Nothing else moves. Using
`sub` as the user key is the single most common way this requirement gets lost.

### 4.4 `maxDevices` is enforced at token issuance, never at socket connect

**Decision:** the device registry lives in FuzeFront's Postgres and is enforced when
a refresh token is issued or rotated. The connection tier only *reads* it.

```
devices(
  user_id UUID, device_id UUID, name TEXT, platform TEXT,
  first_seen_at, last_seen_at, refresh_token_id,
  PRIMARY KEY (user_id, device_id))
```

- enforced at login + refresh  → `maxDevices`, "sign out other device"
- read by Centrifugo           → fan-out targeting only

Why not at connect:

- A device is registered when it receives a **refresh token**, not when it opens a
  socket. A backgrounded mobile app holds no socket and is still an active device;
  enforcing at connect would count it as free.
- Enforcing at connect produces an incoherent state — user is at the cap, logged in
  fine, socket silently refuses. Users read that as a broken app.
- Revocation must flow IdP→socket, not the reverse: revoke the refresh token → the
  connection's next auth refresh fails → disconnect.

Dependency direction is one-way: the connection tier consumes device identity and
never owns it.

**Open item (O1):** whether Authentik offers a native per-user concurrent-session
cap is unverified. It does not change this design — enforcement belongs in
FuzeFront either way under C3 — but it may save building the eviction mechanics.

### 4.5 A dedicated edge namespace, and default-deny before node pools

**Decision:** create namespace `fuzeedge` for internet-facing, non-stateful
services — Centrifugo, `a2a-relay`'s replacement, `a2a-gateway`, `handoff-mcp`,
`custom-hostname-api` — and apply a default-deny `NetworkPolicy` in **both**
`fuzeedge` and `fuzeinfra`, with explicit allows.

Ordering matters and is frequently got backwards:

1. **Default-deny NetworkPolicy first.** Highest value, no scheduling changes.
   Until it exists, node pools buy nothing security-wise — pods on different nodes
   still route to each other freely. Today an RCE in the unauthenticated
   `a2a-relay` reaches `postgres:5432`, `redis:6379`, `mongodb:27017`,
   `neo4j:7687` and `elasticsearch:9200` directly.
2. **Namespace second.** Makes the boundary a namespace selector rather than
   per-pod labels, and separates RBAC and ServiceAccounts.
3. **Node pool last.** Justified by the 2026-09-06 incident (monitoring I/O
   starving the API-serving etcd off a shared disk — the reason
   `scripts/label-durable-nodes.sh` and the `apiVip.nodes` priority table exist).
   Connection gateways are fd/memory-bound and spiky and should not share Longhorn
   disks. But a node pool is a **blast-radius** boundary, not a security boundary.
   Doing it first would feel like progress and change nothing about the flat network.

Note: `fuzeinfra.durableToleration` is currently included by every template. Edge
workloads should stop tolerating the durable taint once the pool exists.

## 5. Security remediation folded into this work

These are not separate projects; each one is a precondition or a direct consequence
of the above.

| # | Issue | Fix | Ref |
|---|---|---|---|
| S1 | `a2a-relay` public with no bearer, in-memory state, `pip install` at start | Replace with Centrifugo; JWT against FuzeFront JWKS; delete the relay | §2.4, §4.1 |
| S2 | Flat pod network | Default-deny NetworkPolicy in `fuzeinfra` + `fuzeedge` | §2.3, §4.5 |
| S3 | `elasticsearch` / `chromadb` / `neo4j` published as hostnames, guarded only by the Access wildcard | Remove from the `$routes` map; reach them by port-forward or an authenticated proxy. If a UI is genuinely needed, a dedicated gated Access app, never a wildcard-only host | §2.5 |
| S4 | Consumer auto-PR can publish a `bypass` host for a colliding label; policy is a comment | Add a CI check on `materialized/consumers.tfvars`: reject any label colliding with an infra-owned host (`$routes` keys + `neo4j*`), fail the generating PR | §2.5 |
| S5 | IdP OIDC endpoints public; IdP coupling leaks to the browser | FuzeFront auth proxy, then delete `authentik_oidc_endpoints` + its bypass | §2.6, §4.3 |
| S6 | Traefik 1 replica, no draining, SPOF for all ingress | `HelmChartConfig` → `deployment.replicas: 2` + PDB `minAvailable: 1` | §2.2 |
| S7 | No alert on a public host with zero ready backends | Prometheus rule on `kube_deployment_status_replicas_ready == 0` for deployments behind a bypass host | §2.7 |

S3 and S4 are the pair worth doing together: S3 removes the exposure that exists,
S4 stops it being recreated.

## 6. Migration sequence

Each step is independently shippable and leaves the system better than it found it.

1. **S2 — default-deny NetworkPolicy.** No new services. Largest risk reduction per
   line changed. Ship in audit mode first if the CNI supports it.
2. **S6 — Traefik to 2 replicas + PDB.** One `HelmChartConfig` edit. Removes the
   ingress SPOF before anything depends on long-lived connections through it.
3. **S3 + S4 — de-expose the datastore hostnames and add the collision check.**
4. **Device registry in FuzeFront** (§4.4). Needed regardless of transport, so it
   is not blocked on any Centrifugo decision. Delegated to FuzeFront via `@fuze`.
5. **FuzeFront auth proxy + own-JWKS token issuance** (§4.3 a/b/c), then **S5**.
   Gates Centrifugo, which must validate FuzeFront tokens, not Authentik's.
6. **`fuzeedge` namespace + Centrifugo** (§4.1, §4.5), Redis engine, Kafka consumer.
7. **Migrate `a2a-relay` onto Centrifugo and delete it** (S1). This is the proof
   case: a real WebSocket workload that is currently a `replicas: 1` SPOF with total
   session loss on restart becomes HA as a side effect.
8. **Node pool for `fuzeedge`** (§4.5 step 3), with the durable toleration removed.
9. Migrate `mendys-realtime`, `fuzefront-chat-service`,
   `fuzefront-notification-service` (§2.8) onto the shared tier.

Steps 1–3 are pure hardening and need no decision from step 4 onward. They should
not wait.

## 7. Open questions

- **O1** Does Authentik provide a native per-user concurrent-session cap? Affects
  how much of §4.4's eviction mechanics FuzeFront builds. Does not change the
  enforcement point.
- **O2 — RESOLVED, no blocker.** `NetworkPolicy` enforcement was the one thing that
  could have silently no-op'd S2 (flannel alone does not enforce it). k3s ships an
  embedded kube-router netpol controller that is active unless installed with
  `--disable-network-policy`. That flag appears nowhere in
  `terraform/contabo/provisioning.tf` or `control-planes.tf` — the install line
  (`provisioning.tf:152`) passes only `--tls-san` and `--node-taint`, and the
  cluster runs `flannel-backend: wireguard-native`. Enforcement is on. Still worth
  an empirical confirm (apply a deny-all in a scratch namespace, verify a curl
  fails) before S2 goes wide.
- **O3** Centrifugo licensing: OSS covers everything in §4.1; Centrifugo PRO is a
  paid tier. Confirm nothing in the design depends on PRO features.
- **O4** Does `maxDevices` vary by plan/tenant? If so it reads from the existing
  Unleash/entitlements path rather than a constant.
- **O5** Retention of the Redis Streams recovery buffer — hours, not days. Set per
  channel class; long history belongs in Kafka, not the gateway.
